# ゲームロジック (`/src/hooks/useGameLogic`)

## 概要

`useGameLogic` は、ゲームの中核的なロジックを管理するカスタムフックです。このフックは、`BattleScreen` コンポーネントから利用され、ゲームの状態 (`gameState`) と、その状態を操作するための一連のアクション (`actions`) を返します。

アーキテクチャは関心の分離の原則に基づき、機能ごとに独立した複数のカスタムフック（モジュール）に分割されています。`useGameLogic/index.ts`がこれらのフックを統合し、単一のインターフェースとして提供します。

返されるオブジェクトの構造:
```typescript
{
  gameState, // 現在のゲーム状態のすべて
  actions: { // ゲーム状態を変更するためのすべての関数
    ...
  }
}
```

---

## モジュール詳細

### `useGameLogic/index.ts`

すべてのゲームロジック関連フックを統合するエントリーポイントです。各モジュールから関数をインポートし、`actions`オブジェクトにまとめて`BattleScreen`に提供します。

- **統合されるフック**:
    - `useGameState`: ゲームのコアとなる状態管理
    - `useTurnManagement`: ターン進行のロジック
    - `useBattleSystem`: 戦闘計算
    - `useUnitActions`: ユニットの基本アクション
    - `useEnhancedEngineerActions`: 工兵の特殊アクション
    - `useTransportActions`: 輸送関連のアクション
    - `useSupplyActions`: 補給関連のアクション
    - `useArmyManagement`: ユニットの生産と配置
    - `useReinforcements`: 増援の処理
    - `useUIStates`: UI表示状態の管理

### `gameState.ts` (`useGameState`)

ゲーム全体の状態（State）を`useState`と`immer`を用いて管理する最も基本的なモジュールです。

- **役割**: ゲームの根幹となるデータ（ターン、ユニット、UI表示状態など）を保持し、状態のロード、履歴保存、巻き戻しなどの基本機能を提供します。
- **主要なState (`GameState`型)**:
    - `gameId`, `status`: ゲームセッションIDと状態 (`loading`, `playing`, `gameOver`)
    - `turn`, `activeTeam`: 現在のターン数と行動中チーム
    - `boardLayout`, `units`: マップ情報と全ユニット配列
    - `weather`: 現在の天候
    - `armyFunds`: 各チームの資金
    - `history`: Undo機能のための状態スナップショット配列
    - `battleLogs`: 戦闘ログの配列
    - **UI関連State**:
        - `selectedUnitId`, `selectedUnit`: 選択中のユニット
        - `highlightedTiles`, `reachableTiles`, `attackableTiles`: 各種タイルハイライト用配列
        - `showTurnChangeModal`, `showVictoryModal`, `showProductionModal`など、各種モーダルの表示フラグ
- **主要な関数**:
    - `loadGame(mapId)`: マップデータから新しいゲームセッションを非同期で初期化します。
    - `saveStateToHistory()`: 現在のゲーム状態を`history`配列に保存します。
    - `undoLastAction()`: `history`配列から直前の状態を復元します。
    - `addBattleLogEntry(entry)`: 戦闘ログを`battleLogs`配列に追加します。

### `turnManagement.ts` (`useTurnManagement`)

ターン進行に関するロジックを担当します。

- **役割**: ターン終了時の処理シーケンス（フラグリセット、チーム交代、収入、補給、天候、勝利判定）を実行します。
- **主要な関数**: `handleEndTurn()`
- **処理フロー**:
    1.  行動済みフラグ (`moved`, `attacked`) をリセットします。
    2.  アクティブチームを交代します。
    3.  `Blue`チームのターン開始時、ターン数をインクリメントし、両チームの収入を計算して`armyFunds`に加算します。
    4.  新しいアクティブチームのユニットに対し、`applySupplyOperations()` で補給を適用します:
        - 自軍の都市/首都でHP10回復
        - 弾薬・燃料全回復
        - **補給ユニットの場合、`supplyStock` を `maxSupplyStock` まで回復**
    5.  天候のターン数を更新し、必要であれば新しい天候をランダムに設定します。
    6.  勝利条件（敵ユニット全滅 or 敵首都占領）を判定し、`gameState.status`を更新します。
    7.  ターン変更モーダルを表示し、各種選択状態をリセットします。

#### `applySupplyOperations()` 関数

ターン開始時に各ユニットへ補給を適用する内部関数です。

```typescript
const applySupplyOperations = (unit: Unit, boardLayout: BoardLayout): Unit => {
  // 自軍所有の City または Capital 上にいるかチェック
  const canReceiveSupply = hasValidTile && isValidSupplyTerrain && 
                           hasValidOwner && isOwnedByUnitTeam;
  
  if (canReceiveSupply) {
    // HP・燃料・弾薬の回復（陸上ユニットのみ）
    // ...
    
    // 補給ユニットの場合、supplyStock を最大値に回復
    const unitIsSupplyType = isSupplyUnit(unit);
    const needsSupplyRestock = unitIsSupplyType && 
      unit.supplyStock !== undefined && 
      unit.maxSupplyStock !== undefined && 
      unit.supplyStock < unit.maxSupplyStock;
    const newSupplyStock = needsSupplyRestock ? unit.maxSupplyStock : unit.supplyStock;
    
    return {
      ...unit,
      hp: newHp,
      fuel: newFuel,
      weapons: resuppliedWeapons,
      ...(unitIsSupplyType ? { supplyStock: newSupplyStock } : {})
    };
  }
  return unit;
};
```

### `battleSystem.ts` (`useBattleSystem`)

戦闘処理と戦闘結果の計算を担当します。

- **役割**: ダメージ計算、ユニットの状態更新、戦闘ログの生成、反撃処理、ユニット撃破処理を行います。
- **主要な関数**: `handleAttackWithWeapon(attacker, defender, weapon)`
- **ダメージ計算式**:
    - `基本ダメージ = (武器威力 + 地形攻撃補正) - (防御側防御力 + 地形防御補正)`
    - `最終ダメージ = round(基本ダメージ * ユニットクラスに対する武器特効倍率)`
    - 砲兵による攻撃の場合、防御側の地形防御補正は無視されます。
- **処理詳細**:
    - 攻撃側ユニットの弾薬を1消費し、`attacked`フラグを`true`にします。
    - 計算されたダメージを防御側ユニットのHPから減算します。
    - **反撃**: 砲兵以外の攻撃で、防御側が生存している場合、射程内にいれば最適な武器で自動的に反撃します。
    - **ユニット撃破**: 戦闘後、HPが0以下になったユニットを`units`配列から除去します。
    - `addBattleLogEntry`を呼び出し、攻撃と反撃のログを記録します。

### `unitActions.ts` (`useUnitActions`)

歩兵や車両など、一般的なユニットの基本アクションを処理します。

- **役割**: 移動、占領、搭載、待機アクションを実行します。各アクション実行前に`saveStateToHistory`を呼び出します。
- **主要な関数**:
    - `handleMove(unit, x, y)`: ユニットを指定座標に移動させ、`moved`フラグを立てます。移動可能範囲のハイライトはクリアされますが、ユニットの選択は維持されます。
    - `handleCapture(unit)`: ユニットのいる座標の建物のHPを10減少させます。HPが0になると自軍の建物に変わり、HPが20に設定されます。
    - `handleLoad(unitToLoad, transportUnit)`: `unitToLoad`を`units`配列から削除し、`transportUnit`の`transporting`配列に追加します。
    - `handleWait(unit)`: ユニットの行動を終了させ（`moved`, `attacked`を`true`に）、ユニットの選択を解除します。

### `supplyActions.ts` (`useSupplyActions`)

補給ユニットからの補給アクション（Pull型・フリーアクション）を管理します。

- **役割**: 補給可否の判定、補給の実行、補給ユニットの識別を担当します。
- **主要な関数**:
    - `canSupply(unit, units)`: ユニットが補給を受けられるかを判定します。
    - `executeSupply(unit, supplyUnit)`: 補給を実行し、燃料・弾薬を回復します。
    - `isSupplyUnit(unit)`: ユニットが補給ユニット（SupplyWagon/SupplyTruck）かを判定します。
- **詳細**: [[補給システム]] を参照

### `enhancedEngineerActions.ts` (`useEnhancedEngineerActions`)

工兵ユニットの特殊なアクションを管理します。`engineerActions.ts`は旧版であり、現在は使用されていません。

- **役割**: 資材と資金を消費する工兵専用アクションのロジックとコスト管理、実行可否の検証を担当します。
- **主要な関数**: `handleEnhancedMaterialAction(engineer, action, coords)`
- **処理詳細**:
    - アクションに必要なコスト（資金・資材）が足りているか検証します。
    - アクションが現在の地形で実行可能か検証します（例: `build_bridge`は`River`地形でのみ可能）。
    - 検証をパスした場合、コストを消費し、地形を変化させ、工兵の行動を終了させます。
- **アクションの例**: `build_bridge`, `destroy_bridge`, `build_fortress`, `remove_fortress`

### `transportActions.ts` (`useTransportActions`)

輸送ユニットの特殊アクション（降車）を管理します。

- **役割**: ユニットの降車に関連するUIインタラクションとロジックを処理します。
- **主要な関数**:
    - `startTransportAction(transportUnit)`: 降車させるユニットを選択するためのモーダル (`UnitSelectionModal`) を表示します。
    - `handleTransportTargetSelect(unitToUnload, targetCoords)`: 選択したユニットを、輸送ユニットに隣接する指定座標に降車させます。
    - `confirmTransportAction()` / `cancelTransportAction()`: 降車アクションの確定またはキャンセルを行います。

### `armyManagement.ts` (`useArmyManagement`)

ユニットの生産と軍隊全体の管理を担当します。

- **役割**: 首都でのユニット生産と、シナリオ開始前のユニット配置のロジックを管理します。
- **主要な関数**:
    - `handleUnitProduction(unitTemplate, team)`: 資金が足りていればコストを消費し、新しいユニットを生成して`units`配列に追加します。
    - `handleUnitDeployment(unit, coords)`: ユニットを指定された座標に配置し、`isDeployed`フラグを`true`に設定します。主にゲーム開始前の配置フェーズで使用されます。

### `reinforcements.ts` (`useReinforcements`)

増援部隊の出現ロジックを管理します。

- **役割**: ターン変更処理と連携し、現在のターン・チームに対応する増援を出現させます。
- **主要な関数**: `checkAndApplyReinforcements()`
- **処理フロー**:
    - `gameState`にあらかじめロードされている増援データ (`reinforcements`) から、現在のターンとチームに一致するものを検索します。
    - 該当する増援ユニットを生成し、指定された座標に配置します。
    - 増援出現通知モーダルの表示フラグを立てます。

### `uiStates.ts` (`useUIStates`)

ユーザーインターフェースの状態管理を担当する、新設された重要なモジュールです。

- **役割**: ユニットの選択/選択解除、各種モーダルの表示/非表示、移動・攻撃モードのステートマシンなど、ゲームのコアロジックとは直接関係ないUIの状態を管理します。
- **主要なState**:
    - `movementMode` (`'none' | 'selecting_destination'`): 移動対象選択中の場合に `'selecting_destination'` となり、緑色ヘックスが表示される。ActionPopupはこのモード中に非表示になる。
    - `attackMode` (`'none' | 'selecting_target'`): 攻撃対象選択中の場合に `'selecting_target'` となり、赤色ヘックスが表示される。ActionPopupはこのモード中に非表示になる。攻撃実行後、ユニットは `moved: true, attacked: true` となり操作不可になる。
- **主要な関数**:
    - `selectUnit(unit)`: ユニットを選択状態にし、`selectedUnit`と`selectedUnitId`を更新します。同時に、そのユニットの移動可能範囲 (`reachableTiles`) と攻撃可能範囲 (`attackableTiles`) を計算してstateにセットします。これはUI描画のトリガーとなります。
    - `deselectUnit()`: すべての選択状態とタイルハイライトをリセットします。
    - `showProductionModal(coords)` / `hideProductionModal()`: 生産モーダルの表示を制御します。
    - `showUnitSelectionModal(coords)` / `hideUnitSelectionModal()`: 輸送ユニットからの降車時など、ユニットを選択するモーダルの表示を制御します。
    - `showBattleReport(report)` / `hideBattleReport()`: 戦闘結果レポートの表示を制御します。
