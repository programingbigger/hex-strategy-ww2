1. 天候の追加
   * 現在の天候状態「晴れ(Sunny)」「雨(Rainy)」に加えて、「雪(Snow)」「吹雪(Blizzard)」
     を新たに追加する。
   * 「吹雪」は「雪」よりも激しい天候と位置づける。

#現状のロジックの問題点

  ご提示のコードの課題は、newDuration
  という名前の変数が、天候の「持続時間」ではなく「蓄積レベル」として使われている点です。
  これにより、以下のような不自然な挙動や拡張性の問題が起こり得ます。

   1. 名前と実態の乖離: duration（期間）という名前なのに、中身は
      level（レベル）であり、コードの可読性を下げています。
   2. ロジックの不整合: 地形変化の条件が ['Rain', 'Storm'].includes(nextWeather) && 
      newDuration >= 3
      となっています。これは「雨が降っており、かつ湿り気レベルが3以上」という意味です。
      つまり、湿り気レベルが3以上でも、天気が一瞬でも「晴れ」に変われば、そのターンは地
      形変化が起こらないことになり、不自然です。（地面は濡れたままのはず）
   3. 拡張性の限界: このまま「雪」を実装しようとすると、snowLevel
      のような変数が別途必要になり、newDuration と snowLevel
      という2つの「蓄積レベル」を管理する必要が出てきて、ロジックが複雑化します。

上記の問題点を解決するために、現在の天候ロジックnewDurationによるトリガーを以下のように環境レベルというものを定義します。

#改善案：単一の「環境レベル」モデルへのリファクタリング

  現在の「蓄積レベル」という概念は素晴らしいので、これを正式なものとして採用し、ロジック
  を整理します。

  environmentalLevels を導入します。

   3   wetness: 0, // 地面の湿り気レベル (旧 newDuration

   4   snow: 0,    // 積雪レベル (新規)
   5 });

   * 積雪レベル 3:

       * 「雪原」は新たな地形として定義され、独自の移動コストや防御効果を持つ。
   * 積雪レベル 5:
       * 地形「川(River)」が「凍結した川(FrozenRiver)」に変化する。
       * 「凍結した川」上は、全ての陸上ユニットが通常の陸地と同様に移動可能になる（渡河

       * 「凍結した海」上は、全ての陸上ユニットが移動可能になる。
